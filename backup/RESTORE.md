# Восстановление полного снимка

Репозиторий содержит удобный для просмотра исходный код. Полный архив ресурсов находится в закрытом релизе `snapshot-2026-09-23-v60`.

1. Авторизоваться в GitHub CLI под аккаунтом с доступом к этому репозиторию.
2. Скачать **все** файлы `arxvr-full-snapshot.7z.*` из релиза в одну пустую папку, а также `SHA256SUMS.txt`.
3. Сверить SHA-256 каждого тома с `SHA256SUMS.txt` (`Get-FileHash -Algorithm SHA256`).
4. Проверить архив: `7z t arxvr-full-snapshot.7z.001`.
5. Распаковать первый том: `7z x arxvr-full-snapshot.7z.001 -oF:\ArxVR-Restore`. Все остальные тома будут подхвачены автоматически. Не распаковывать поверх действующей разработки.

Структура распакованных данных:

| Каталог | Содержимое |
| --- | --- |
| `workspace/` | Рабочие файлы из `F:\CODEX\ArxFatalis VR`, включая движки, зависимости, ресурсы, APK и все диагностики |
| `original-game/` | Оригинальная Steam-папка Arx Fatalis, включая игровые PAK и существующие сохранения |
| `device-game-files/` | Копия `/sdcard/Android/data/com.arxvr.android/files` с PICO, без изменения устройства |
| `earlier-session/` | Более ранние скриншоты, видео и инструменты этой задачи |
| `user-reference-images/` | Скриншоты ошибок, явно приложенные пользователем в этой задаче (если исходные файлы ещё доступны) |

`files-sha256.csv` содержит путь, размер и SHA-256 каждого файла этого снимка; `excluded.csv` — список исключённых каталогов/файлов. Копирование с устройства выполнялось при работающем приложении: это файловая копия, не атомарный snapshot Android и не дамп памяти процесса.

Проверить все распакованные файлы можно скриптом из этого репозитория:

```powershell
pwsh -File .\backup\Verify-Snapshot.ps1 -ExtractedDirectory F:\ArxVR-Restore
```

Для привычных путей восстановите `workspace` в `F:\CODEX\ArxFatalis VR` или измените локальные пути в скриптах. Они сохранены без переработки. `V:` использовался как `subst` для короткого пути к этой папке.

## Внешний Android toolchain

Исходная сборка использовала внешний каталог `F:\CODEX\android-toolchain`, который не является частью каталога этого проекта и не включён в архив:

- Android SDK platform 35, build-tools 35.0.0;
- Android NDK 27.0.12077973;
- CMake 3.22.1 для Android Gradle проекта;
- JDK 17.0.20+8;
- `platform-tools/adb.exe`.

Внутренний `workspace/toolchain` сохранён, в том числе локальный набор MSVC для регрессионных тестов. Gradle caches исключены; при чистой сборке зависимости нужно получить заново. Это резервная копия рабочего состояния, не доказательство воспроизводимости на чистом ПК.

## Важное о последнем host build

После изменения `IApplication` нужна полная пересборка host с `ndk-build -B`, иначе старые объектные файлы могут сохранить несовместимую таблицу виртуальных функций и давать чёрный экран.

Параметры использовавшегося вызова (пути заменить при необходимости):

```powershell
subst V: 'F:\CODEX\ArxFatalis VR'
& 'F:\CODEX\android-toolchain\sdk\ndk\27.0.12077973\ndk-build.cmd' -B `
  'NDK_PROJECT_PATH=null' `
  'APP_BUILD_SCRIPT=V:/PICO-OpenXR-Demos/app/src/main/cpp/Android.mk' `
  'NDK_APPLICATION_MK=V:/PICO-OpenXR-Demos/app/src/main/cpp/Application.mk' `
  'APP_ABI=arm64-v8a' 'NDK_ALL_ABIS=arm64-v8a' 'APP_PLATFORM=android-29' `
  'NDK_OUT=V:/PICO-OpenXR-Demos/app/build-codex/intermediates/cxx/Debug/1q6z8e58/obj' `
  'NDK_LIBS_OUT=V:/PICO-OpenXR-Demos/app/build-codex/intermediates/cxx/Debug/1q6z8e58/lib' `
  'C_SHARED_INCLUDE=V:/' -j6 NDK_DEBUG=1 openxr_demos
```

Затем повторить с теми же параметрами без `-B` и без заключительного `openxr_demos`, чтобы штатный install/strip шаг обновил `lib/arm64-v8a/libopenxr_demos.so`, используемый упаковкой. Одного файла из `obj` недостаточно.

Упаковка `tools/package-arxvr-qa.ps1` выполнялась на основе v58 и меняла только OpenXR host и подпись. Архив содержит v58, v60 и их зависимости. Не брать неподходящую старую библиотеку из `ArxVR-Android/app/src/main/jniLibs`.

## Подпись и установка

Закрытый ключ, использованный для v60, намеренно не загружен. Он остаётся на исходном компьютере. Для обновления уже установленного приложения с сохранением данных требуется та же подпись. Новая debug-подпись не позволит просто обновить старое приложение; **не удаляйте приложение и не очищайте его данные**, чтобы обойти эту ошибку. Сначала сохраните данные и решите вопрос подписи.

В релизе лежит уже подписанный v60 APK. Его можно установить поверх совместимой подписанной сборки через `adb -s <PICO_SERIAL> install -r <apk>`. Всегда указывать серийный номер нужного PICO: к компьютеру также был подключён другой Android-телефон, к которому эта задача не относится.
